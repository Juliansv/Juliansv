# Project Image Blur Placeholder Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use
> superpowers:subagent-driven-development (recommended) or
> superpowers:executing-plans to implement this plan task-by-task. Steps use
> checkbox (`- [ ]`) syntax for tracking.

**Goal:** Eliminate the hero image pop-in on the single project page (and
project cards on the home page) by pre-generating blurred LQIP data URLs at
build time and injecting them into `next/image` via a wrapper component.

**Architecture:** A build-time `tsx` script reads every `projects[].image` path
from `src/data/projects`, runs each file through `plaiceholder`, and writes a
keyed `Record<string, string>` to `src/data/generated/image-placeholders.ts`. A
new `<ProjectImage>` component looks up the `blurDataURL` for a given `src` and
forwards to `next/image` with `placeholder="blur"`. Three existing consumers
swap `Image` → `ProjectImage` with no other prop changes.

**Tech Stack:** Next.js 15.3, React 19, TypeScript (strict), `plaiceholder` +
`sharp` (build-time image processing), `tsx` (TS script runner), Vitest + React
Testing Library (tests), pnpm.

`docs/superpowers/specs/2026-04-22-project-image-blur-placeholder-design.md`

### Task 2: Create the generation script

**Files:**

- Create: `scripts/generate-image-placeholders.ts`

- [ ] **Step 1: Create the script**

Create `scripts/generate-image-placeholders.ts` with the following contents:

```ts
import { readFile, writeFile, mkdir } from "node:fs/promises";
import path from "node:path";
import { getPlaiceholder } from "plaiceholder";
import { projects } from "../src/data/projects";

const PUBLIC_DIR = path.join(process.cwd(), "public");
const OUTPUT_FILE = path.join(
	process.cwd(),
	"src",
	"data",
	"generated",
	"image-placeholders.ts"
);

async function generateFor(imagePath: string): Promise<[string, string]> {
	const absolute = path.join(PUBLIC_DIR, imagePath);
	let buffer: Buffer;
	try {
		buffer = await readFile(absolute);
	} catch (err) {
		throw new Error(
			`Cannot read image referenced by projects data: ${imagePath} (resolved to ${absolute}). ${(err as Error).message}`
		);
	}
	const { base64 } = await getPlaiceholder(buffer, { size: 10 });
	return [imagePath, base64];
}

async function main(): Promise<void> {
	const imagePaths = projects.map((p) => p.image);
	const entries = await Promise.all(imagePaths.map(generateFor));
	entries.sort(([a], [b]) => a.localeCompare(b));

	const body = entries
		.map(
			([key, value]) => `\t${JSON.stringify(key)}: ${JSON.stringify(value)},`
		)
		.join("\n");

	const file = `// AUTO-GENERATED by scripts/generate-image-placeholders.ts. Do not edit by hand.
// Run \`pnpm generate:placeholders\` to refresh.

export const imagePlaceholders: Record<string, string> = {
${body}
};
`;

	await mkdir(path.dirname(OUTPUT_FILE), { recursive: true });
	await writeFile(OUTPUT_FILE, file, "utf8");
	console.log(
		`Wrote ${entries.length} placeholder(s) to ${path.relative(process.cwd(), OUTPUT_FILE)}`
	);
}

main().catch((err) => {
	console.error(err);
	process.exit(1);
});
```

**Notes for the implementer:**

- The script uses a relative import (`../src/data/projects`) rather than the
  `@/` alias so it runs under `tsx` without extra path-alias configuration.
- `getPlaiceholder(buffer, { size: 10 })` returns `{ base64, img, css, svg }`;
  we only need `base64` (a data URL ready for `next/image`'s `blurDataURL`
  prop).
- Keys are sorted alphabetically so diffs stay stable across regenerations.
- On a missing file, the script throws a descriptive error and `process.exit(1)`
  fails the build.

- [ ] **Step 2: No standalone test for the script**

Rationale: this is a build-time utility exercised end-to-end in Task 4
(generate + inspect output) and Task 7 (full `pnpm build`). Unit-testing
plaiceholder's output would be coupling to the library.

- [ ] **Step 3: Implement the component**

Create `src/components/ProjectImage.tsx`:

```tsx
import Image, { type ImageProps } from "next/image";
import { imagePlaceholders } from "@/data/generated/image-placeholders";

type ProjectImageProps = Omit<ImageProps, "placeholder" | "blurDataURL"> & {
	src: string;
};

export const ProjectImage = ({ src, ...rest }: ProjectImageProps) => {
	const blurDataURL = imagePlaceholders[src];
	return (
		<Image
			src={src}
			{...rest}
			{...(blurDataURL && { placeholder: "blur" as const, blurDataURL })}
		/>
	);
};
```

**Notes for the implementer:**

- Named export only (project convention; `FeaturedHeroProject` uses a named
  export).
- Return type is inferred — matches the convention in existing components
  (`FeaturedHeroProject.tsx` at `src/features/front/projects/components/`).
  Explicit return types are not used on React components in this codebase.
- The `src` type is narrowed from `ImageProps["src"]` (`string | StaticImport`)
  to `string` to match the data layer and the placeholder map key type.
- The spread-on-falsy pattern `{...(blurDataURL && { … })}` passes nothing when
  the key is absent, which keeps `next/image`'s default `placeholder="empty"`
  behavior.
