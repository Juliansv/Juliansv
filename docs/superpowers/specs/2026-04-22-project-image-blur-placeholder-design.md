# Project Image Blur Placeholder

**Date:** 2026-04-22 **Status:** Design approved, pending implementation plan

## Problem

On the single project page (`/project/[slug]`), the hero image renders with a
pop-in: the reserved slot is visible immediately (width/height are set, so no
geometry shift), then the actual `.webp` appears a second or two later with a
visible flash. The effect is most noticeable on slower networks and during route
transitions.

Project images also appear on the home page (`Projects.tsx` card grid,
`FeaturedHeroProject.tsx` hero card) with the same behavior.

The goal is to show a low-resolution blurred preview of each image immediately,
which then cross-fades to the full-quality image once loaded. This is the
standard LQIP (low-quality image placeholder) pattern and is what `next/image`'s
`placeholder="blur"` prop is designed for.

## Approach

Pre-generate a base64-encoded blur data URL for every project image at build
time, store it in a generated TypeScript module, and inject it into `next/image`
via a thin wrapper component. The existing `Project.image: string` data shape is
preserved.

**Why build-time, not runtime:** zero per-request cost, placeholders ship in the
page HTML, no `sharp` in the server runtime.

**Why a wrapper component, not inline:** three consumer call sites today (and
likely more later). Centralizing the placeholder lookup avoids drift.

## Architecture

```
public/images/projects/*.webp
            │
            ▼  build time (pnpm generate:placeholders, wired via prebuild)
scripts/generate-image-placeholders.ts
  ├─ reads projects[].image from src/data/projects/index.ts
  ├─ resizes + blurs each file via plaiceholder
  └─ writes src/data/generated/image-placeholders.ts
            │
            ▼  runtime (server components)
<ProjectImage src={project.image} … />
  ├─ looks up blurDataURL from the generated map
  └─ renders next/image with placeholder="blur" + blurDataURL
```

The script iterates over `projects[].image` (the data layer is the source of
truth for what's rendered), not over `fs.readdir(public/images/projects)`
(orphan files should not be processed; missing files referenced by data should
fail the build loudly).

## Components

### 1. Generation script — `scripts/generate-image-placeholders.ts`

**Responsibilities:**

1. Import `projects` from `@/data/projects` to enumerate image paths.
2. For each path, resolve to `public/<path>` on disk.
3. Call `getPlaiceholder(buffer, { size: 10 })` → `{ base64 }`.
4. Collect results into a `Record<string, string>` keyed by the original public
   path.
5. Write `src/data/generated/image-placeholders.ts` with a stable key order
   (sorted) so diffs stay clean.

**Failure modes (script throws, build fails):**

- Missing file on disk (referenced by data but not present in `public/`).
- Unreadable file / unknown format.

**Output file header:**

```ts
// AUTO-GENERATED by scripts/generate-image-placeholders.ts. Do not edit by hand.
// Run `pnpm generate:placeholders` to refresh.
```

### 2. Generated module — `src/data/generated/image-placeholders.ts`

```ts
export const imagePlaceholders: Record<string, string> = {
	"/images/projects/abogadaprevisional.webp": "data:image/webp;base64,…",
	// …one entry per project image, sorted by key
};
```

Committed to git. Marked `linguist-generated=true` via `.gitattributes` to
reduce review noise.

### 3. Wrapper component — `src/components/ProjectImage.tsx`

```ts
import Image, { type ImageProps } from "next/image";
import { imagePlaceholders } from "@/data/generated/image-placeholders";

type ProjectImageProps = Omit<ImageProps, "placeholder" | "blurDataURL"> & {
  src: string;
};

export const ProjectImage = ({ src, ...rest }: ProjectImageProps) => {
  const blurDataURL = imagePlaceholders[src];
  return (
    <Image
      src={src}
      {...rest}
      {...(blurDataURL && { placeholder: "blur", blurDataURL })}
    />
  );
};
```

**Behavior on missing placeholder:** falls back to `placeholder="empty"`
(current behavior). No crash, no visual regression for that one image. The
build-time script is the authoritative guard; this is a runtime safety net.

**Does not set** defaults for `width`/`height`/`alt`/`className`/`priority` —
call sites retain full control. The wrapper only injects the blur.

## Integration

Three call sites swap `Image` → `ProjectImage`:

- `src/features/front/projects/components/SingleProject.tsx:71` — hero image,
  wrapped in `<Zoom>`. Also drop `loading="eager"` since it's redundant with
  `priority` and Next warns on the combo.
- `src/features/front/projects/components/FeaturedHeroProject.tsx` — featured
  hero card on home.
- `src/features/front/projects/components/Projects.tsx` — project card grid on
  home.

No prop changes required beyond the import swap. View transitions
(`viewTransitionName` on the parent `<div>` in `SingleProject.tsx:69`) are
untouched; blur placeholders render as a background under `next/image` and do
not interfere with the View Transition API snapshot.

## Tooling & wiring

**Dependencies (devDependencies):**

- `plaiceholder` — blur generation API
- `sharp` — image processing (plaiceholder peer dep; Vercel provides native
  binaries)
- `tsx` — run the TS script without a build step

**`package.json` scripts:**

- `"generate:placeholders": "tsx scripts/generate-image-placeholders.ts"`
- `"prebuild": "pnpm generate:placeholders"` (new — no existing prebuild)

**Git:**

- `src/data/generated/image-placeholders.ts` is committed.
- `.gitattributes`: `src/data/generated/** linguist-generated=true`.

## Testing

**Unit test** — `src/components/ProjectImage.test.tsx`:

- With a `src` present in a mocked placeholder map → `<img>` is rendered with
  `placeholder="blur"` threaded through.
- With a `src` absent from the map → component still renders without throwing.

The generated module is mocked in the test so the unit test does not depend on
the real generated content.

**Manual verification checklist** (run before declaring done):

1. `pnpm generate:placeholders` — generated file contains an entry for every
   `project.image`.
2. `pnpm build` — prebuild hook runs; build succeeds end-to-end.
3. `pnpm dev`, then on `/project/<slug>` with DevTools network throttled to Slow
   3G: confirm blurred preview is visible immediately on render, then crisp
   image fades in. Repeat on `/` (home grid + featured hero).
4. No Next.js warnings in the browser or server console (e.g., `priority` +
   `loading`).

**Explicitly out of scope:**

- Visual regression / Lighthouse testing.
- E2E tests for throttled-network scenarios.
- Script smoke tests (manual check is sufficient for a portfolio).

## Risks & scope guardrails

- **Bundle size.** Blur base64 strings are ~1-2 KB each; 8 projects ≈ 10-15 KB
  added to any page importing the map. Acceptable. Revisit (e.g., route-scoped
  maps) if the project list grows significantly.
- **`sharp` native binaries.** Vercel's build image provides Linux binaries.
  Local dev on Linux (per user's environment) is also fine. No action needed.
- **`next/image` API.** `placeholder="blur"` + `blurDataURL` has been stable
  since Next 10; current project is on 15.3. No risk.
- **Out of scope:** experience logos, archive page images (if any) beyond
  project images, refactoring `Project.image` to a static import, image CDN
  work, experience page hero images.

## Success criteria

- Hero image on `/project/[slug]` shows a blurred preview immediately on first
  paint.
- No layout shift (already the case; width/height are set).
- Project cards on `/` and the featured hero also show blurred previews.
- Build fails if an image referenced by `projects[].image` is missing from disk.
- No runtime crash when a placeholder is unexpectedly missing from the map.
